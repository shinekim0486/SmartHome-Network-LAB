# 학생별 학습기억 설계

Gemini 대화 자체에 장기 기억을 맡기지 않습니다. 모든 학습 사실은 `server/data/smarthome_lab.db`의 SQLite에 저장하고, 다음 차시에 필요한 요약만 프롬프트로 다시 제공합니다.

## 6개 학습 영역

1. `students`: 학번/고유ID, 별명, 생성일
2. `lesson_progress`: 1~48차시 상태와 시작·완료 시각
3. `chat_logs`: 학생 질문, Gemini 응답, 차시, 시각
4. `evidence`: Wireshark/TShark 증거, 패킷 번호, 필터
5. `judgements`: AI 사용 전 최초 판단, AI 가설, 최종 판단, 채택 가설
6. `student_memory`: 강점, 어려운 개념, 최근 실수, 지난 차시 요약, 지도 규칙

실제 테이블 정의는 `server/database.py`에 있습니다. 데이터베이스 파일은 첫 서버 실행 때 자동 생성되며 Git에는 커밋되지 않습니다.

## 필수 순서

1. 학생 로그인
2. 차시 진행 시작
3. 최초 판단 저장
4. Wireshark/TShark 증거 저장
5. Gemini 질문과 응답 저장
6. 최종 판단과 채택 가설 저장
7. 차시 완료
8. 교사가 강점·어려움·반복 오류·지난 차시 요약 보정
9. 다음 차시용 Gemini 프롬프트 생성

서버는 최초 판단 없이 Gemini 대화 로그를 저장하려는 요청을 거부합니다. 이 규칙은 화면뿐 아니라 API에도 적용됩니다.

## 개인정보와 인증

현재 로그인은 교실 내부 MVP를 위한 학번/별명 식별 방식이며 비밀번호 인증이 아닙니다. 인터넷에 배포하기 전에는 학교 인증, 교사 권한, 세션 만료, HTTPS, 백업·파기 정책을 추가해야 합니다. Gemini에는 학번이나 실명 대신 요약된 학습기억만 전달하세요.
