# 교사용 운영 가이드

## 수업 전

- Python, VS Code, Wireshark/Npcap 설치와 루프백 캡처를 점검합니다.
- 교실 네트워크에서 허용되는 캡처 범위를 공지합니다.
- 2인 1조 권장 역할: 드라이버(코드/명령), 관찰자(패킷/증거). 매 차시 교대합니다.

## 평가(차시당 10점)

- 실행 재현성 2점: 명령과 환경이 명확함
- 증거 정확성 3점: 프레임·필드가 주장을 직접 뒷받침함
- 학생 판단 3점: AI 답변을 복사하지 않고 반례를 검토함
- 수정·재검증 2점: 한 변인을 바꾸고 결과를 다시 확인함

정답 패킷 번호는 환경마다 달라집니다. 번호 자체보다 학생이 선택한 패킷과 판단의 연결을 평가하세요.

## GitHub 제출 운영

1. 학생에게 `student-template/`를 배포하고 학생 본인 GitHub에 새 공개 저장소를 만들게 합니다.
2. 학생은 차시별 `labs/XX` 폴더, 코드, 증거 기록을 커밋한 뒤 학생 화면에 저장소 주소를 제출합니다.
3. 교사는 `teacher.html`에서 README와 차시 폴더 자동 검사 결과, 최신 커밋, 학생 회고를 확인합니다.
4. 피드백과 함께 `수정 요청` 또는 `승인` 상태를 저장합니다.

공개 저장소에 학생의 실명·학번을 올리도록 요구하지 마세요. 플랫폼의 학번 정보와 GitHub 사용자명을 외부에 함께 공개하지 않도록 주의합니다.

## 학생 학습기억 보정

교사용 화면에서 학생별 강점, 어려운 개념, 반복 오류, 지난 차시 요약을 기록합니다. 이 정보는 다음 차시 Gemini 프롬프트에 들어가므로 관찰 가능한 학습 증거에 근거해 간결하게 작성합니다. 학생의 성격이나 능력을 단정하는 표현 대신 “SYN/ACK을 응답 패킷으로 연결하는 데 추가 연습 필요”처럼 수정 가능한 학습 행동을 기록하세요.
